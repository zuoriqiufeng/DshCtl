## 2 逐条证据

### D-1 插件间零跨插件 import · 松契约成立（正向基线）
- **源码一**：顶层 import 图无 `pluginA -> pluginB` 边；各插件只 import 自身 + `node:*` + `@deepseek-ai/*`（`ops-api/index.ts`、`dsh-plugin/index.ts` 等）。仅 `code/scripts/*`（生成/冒烟工具链）跨目录读插件源码（如 `gen-intent-taxonomy.ts` import `../dsh-plugin/constants.ts`、`../intent-router/taxonomy.ts`——工具链允许，非运行时依赖）。
- **跨文件/运行**：`ctx.provide('bknFeedbackAdmin',…)`（`bkn-feedback/index.ts`）、`ctx.provide('skillManagerAdmin',…)`（`ops-skill-manager/index.ts`）、`ctx.provide('observability',…)`（`dsh-observability/index.ts`）与 `ops-api/index.ts` 的 `ctx.get('observability')`/’ctx.get('bknFeedbackAdmin')’/’ctx.get('skillManagerAdmin')’ 逐个同名命中；dsh-plugin `ctx.emit('bkn/risk-hit')` 由 dsh-observability `ctx.on('bkn/risk-hit')` 消费（事件契约）。6 插件 Tarjan 环检测全部 pass。

### D-2 intent-router 自包含副本缺漂移断言
- **源码一**：`intent-router/aliases.ts:4`「2026-10-21 从 code/dsh-plugin/constants.ts 复制（ERROR_ALIASES/SYMPTOM_ALIASES 两表 1:1）」；`intent-router/bm25.ts:4`「从 code/dsh-plugin/bm25.ts 复制（实现体 1:1）」；`intent-router/logfile.ts:6,24`「rotateIfNeeded 已内联本文件（2026-10-21 S1 自包含整改…源变更需人工同步）」。
- **跨文件/运行**：S0/S1 硬规则 3（`plugin-boundary-direction.md` §5）规定「跨插件复用唯一合法路径②：纯原语 → 本插件内副本 + **漂移断言（黄金输入同结果）**」，且 S1 §4 施工单 step1 验收要求「…自测全绿且**新增漂移断言**」。但 `grep 漂移|drift|黄金|同输入` 于 intent-router = 0；`intent-router/self-test.ts` 不含任何 `dsh-plugin` 引用（无法比对副本与源）。concluded：3 组副本均无自动化同步守护，靠注释承诺。

### D-3 dsh-plugin 内同一默认路径双源
- **源码一**：`dsh-plugin/supplement.ts:21` `gapLogPath: process.env.I2STREAM_GAP_LOG ?? '/hdd/demo/public/i2stream-bkn/logs/gap_log.jsonl'`；`dsh-plugin/index.ts:57` `EXTERNAL_DEFAULTS.gapLogPath: '/hdd/demo/public/i2stream-bkn/logs/gap_log.jsonl'` —— 两个同名默认值**逐字相同**、彼此无引用。
- **跨文件/运行**：`index.ts:156` `configureGapLog(deps.gapLogPath)` 在 apply 时用解析链（config→env→EXTERNAL_DEFAULTS）覆盖 supplement 默认，故 supplement 默认只是「configureGapLog 未被调用」时的兜底；两条不同解析链各自独立持有同一字面量 → 日后任一侧改动就会静默分叉（违反 AGENTS §3「约定优先于配置 / 防双源漂移」回退单层铁律的精神）。

### D-4 别名域数据三处独立表示（跨文件撕裂 + 冗余）
- **源码一**：权威表 `dsh-plugin/constants.ts` 的 ERROR_ALIASES / SYMPTOM_ALIASES；`intent-router/aliases.ts` 手拷副本；`intent-router/index.ts:29` import 该副本、`:261` `buildAliasIndex(intents,{ symptom: SYMPTOM_ALIASES, error: ERROR_ALIASES })` 运行时使用副本。

## 3 结论

1. **扁平、无环、无跨插件 import 是本仓最稳的分层资产**：6 插件顶层 0 相互边、0 有向环；跨插件只走 `ctx.get/provide`（服务名）与 `ctx.on/emit`（事件），ops-api 对 observability/bkn-feedback/skill-manager 的消费全部同名命中——对照 AGENTS §1 边界表与 §3，边界纪律执行到位（D-1，confirmed 正向）。

2. **重构债务集中在「复制即散、守护没跟上」**：S1 自包含整改把 dsh-plugin 的别名表 / bm25 / rotateIfNeeded 复制进 intent-router，却**一处漂移断言都没有**（硬规则 3 明确要求），logfile.ts 自认「需人工同步」——这是未来最可能静默错位的点（D-2）。配套地，dsh-plugin 内部同一默认路径双源（D-3）、别名数据三处独立表示且手拷副本与生成快照并存（D-4），都是「约定优先于配置 / 防双源漂移」(R8) 红线下的实质违约。

3. **方向文档是过时的死表**：`plugin-boundary-direction.md` §2.3 仍把已消除的 3 处耦合列为活耦合并据此下「pack 必 ERR_MODULE_NOT_FOUND」的结论，头部状态未随 2026-10-21 的部分实施流转——文档债会诱导重复返工与误判（D-5）。

4. **单一职责整体健康，仅两处灰区**：tools.ts 注册中枢偏大（D-7）、ops-api 硬编码服务名隐式扇出到 3 兄弟插件（D-6）——均为可接受的 observation，不构成阻断。
