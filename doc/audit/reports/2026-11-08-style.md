## 3 结论

1. **工具数口径是本次最重的单一来源/命名失守**：插件已注册 14 个工具（批次 C1/C2 的 check_plan、diagnose_mechanism），但 diff 出 manifest provides 只有 12 且缺新工具、入口注释写 4、README 内部 12 与 4 并存、tools.ts 注释写"前 10 个"、AGENTS/主 README 写 12。按文档数工具会被误导；以 provides 为准还会漏掉 2 个真实工具。
2. **格式门禁整体缺席**：仓库无 lint/typecheck/prettier 与 CI 环节，仅靠 vite build（esbuild 不 typecheck）+ self-test，且 doc 显式记录"tsc --noEmit 过滤仅存量错误"的降级口径；源内 eslint-disable 是悬空指令。符合"门禁未真正入链"的最坏情形。
3. **跨文件常量/环境键单一来源未建立**：embed/qdrant/collection/gapLog 默认值在 index.ts、retrieval.ts、supplement.ts、intent-router .yml 四处以字面量重复；I2STREAM_QDRANT_COLLECTION 已在代码/README 任 env 哨兵却未登记进 plugin external 清单；CI 环节数（9 实际 vs AGENTS 6 / dshctl-README 5）、embed 侧车 env 前缀（.py 用 EMBED_*、.yaml/TS 用 I2STREAM_*）构成文档口径与命名一致性问题。
