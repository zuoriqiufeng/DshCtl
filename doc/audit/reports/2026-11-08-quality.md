## 2 逐条证据

### D-1（confirmed·中）H-15 降级吞错普遍缺 warn 日志

- **源码证据（第一证）**：`code/dsh-plugin/supplement.ts:142-153` `logGap()` 的写失败分支为裸 `catch { /* 静默，不影响主流程 */ }`，无 warn；`supplement.ts:137-139` rotate 失败 `catch{return false}` 无 warn。`code/dsh-observability/index.ts:105-107` 清理超期文件裸 `catch { /* 静默 */ }`；`index.ts:110-117` rotate 失败 `catch { /* 轮转失败不抛 */ }`。`code/bkn-feedback/index.ts:97-101` 轮转裸 catch。
- **跨文件证据（第二证）**：AGENTS.md §3 降级铁律（H-15）原文"失败路径返回空值/静默 **+ warn 日志**，绝不抛错"。dsh-observability `index.ts` 自述纪律同为"采集/写盘失败静默丢弃 + warn"。同插件内对照：`dsh-observability/index.ts:117` 落盘失败有 `warn(...)`，但轮转/清理/读坏行（:68,:81,:105-107,:138,:142）均静默——纪律执行不对称。
- **影响**：gap 台账/观测轮转写入失败不进日志，运维无法发现"台账在无声丢数据"，与 H-15 的 warn 要求不符。

### D-2（confirmed·中）usage 台账损坏后静默空表覆盖

- **源码证据（第一证）**：`code/ops-skill-manager/store.ts:31-41` `readUsage()` 在 `JSON.parse` 抛错或形状非法时 `catch { return {} }`（静默空表）；`store.ts:42-50` `writeUsage()` 为"tmp+rename 全量覆盖"。`bump()`（:52-78）先读后写:读得空表→写回仅含当前技能的单条记录。
- **跨文件证据（第二证）**：`ops-skill-manager/index.ts` 注册的 skill 工具/curator 直接调 `bump/setState`，无读失败兜底合并、无 warn；curator.ts 迁移同样走 `readUsage`→`writeUsage`。该模块是纯函数、无 logger（import 仅 node:fs），_不存在任何 warn 通道_。
- **影响**：若 `.usage.json` 损坏/部分写坏，台账其余技能计数会被静默清空，且无人察觉。属"吞错 + 数据完整性"双料。

## 3 结论

1. **可观测已去黑盒（正向）**：usage/risk/gap 三类台账在生产路径真实写盘（afterTurn→recordUsage、pre-execute→bkn/risk-hit、工具 wrap→logGap、skill_manage→appendCorrection），插件在 `domains/ops/domain.yml` 挂载、落盘目录显式，且有 /v1/metrics 等读接口与文档 live 实测。此结论双证充分（D-10）。
2. **H-15 落实不对称是首要问题（D-1+D-2）**：降级"静默返回空"普遍实现到位，但"warn 日志"大量 catch 缺失；其中 `ops-skill-manager` usage 台账读损坏→静默空表→下一次写覆盖，是唯一会把**既有数据**抹掉的吞错点（D-2），建议优先加 warn + 读失败不覆盖（缺省保留旧表）。
3. **测试为"断言型但非 API 级"，且 eval 有覆盖缺口（D-7/D-8/D-9）**：ci.sh 九环节与 eval hardline（零误采纳+覆盖≥85%）确为断言型、非只跑不查；但 self-test 停在单元/集成级（不经过工具注册边界/真实 HTTP），且 eval 标注集对 `search_qdrant`/`process_debug` 两意图零正样本——无回归防线。这是测试充分性的两个真实缺口。
4. **死代码治理欠账（D-3/D-4/D-5/D-6）**：≥11 处未使用 import、2 个死导出函数、1 个只写不读字段（`sequenceSemantic`，自认"数据休眠"）、1 个无消费者装饰字段（`_coverage_pending`），叠加无 noUnusedLocals/eslint，属"逐仓堆积"型死代码。

**按影响排序的三条最重要**：D-2（台账被静默清空，数据完整性）> D-1（H-15 warn 纪律大面积缺失，运维黑盒）> D-7（injectable 意图零回归防线）+ D-8（无 API 级断言）。

**阻塞性**：无（无红线级逻辑错误；D-7/D-8 为测试改进项非阻塞）。
